[Term-CORE] 계약 기간 · 갱신 · 만료 · 기준액
- [공통] 계약 기간 필드(합의서 v3.9.11 §5.5) — 계약 시작일(start_date) · 최초 종료일(initial_end_date, 계약서 종료일) · 현재 종료일(current_end_date, 자동 갱신 반영 · 시스템 계산 · 직접 입력 불가) · 만료 알림 기준(contract_expiry_alert_days, 기본 30일 · 부록 B). 알림 기준 아래에 "종료일까지 N일" / "종료일 N일 경과"를 표시한다
- [공통] 종료 방식(renewal_type) — 자동 갱신 AUTO(종료일이 지나면 같은 조건으로 갱신 단위만큼 연장) / 수동 종료 MANUAL(종료일에 만료 · 이어가려면 후속 계약을 새로 등록). 갱신 단위(renewal_term_months: 1년 · 2년 · 3년)와 [다음 자동 갱신 중단](renewal_stop_yn — 다음 갱신만 막고 종료일은 유지)은 자동 갱신일 때만 열린다
- [공통] 자동 갱신은 새 계약을 만들지 않는다 — 같은 계약의 계약 기간 이력(contract_terms)에 회차 행(예: 1회차(최초) · 2회차(1차 갱신))을 쌓는다. 현재 종료일은 갱신 이력의 확정 종료일 기준이며 날짜 경과만으로 이 화면에서 갱신을 실행하지 않는다 — 이전 판의 「만료 D-30 에 [대기] 계약 자동 생성」을 대체한다(확인 필요 사항 7 · 11)
- [공통] 계약 발생 구분 — 신규 계약 / 승계 계약. 승계 계약이면 선행 계약이 필수다 "승계 계약의 선행 계약을 입력해 주세요." 중도 해지일은 계약 상태가 중도 해지일 때만 열리고 필수이며 계약 기간 안이어야 한다 — "중도 해지일을 입력해 주세요." / "해지일은 계약 기간 안에 있어야 합니다."
- [공통] 최소 지급 기준액(min_payout_limit, 기본 100,000원 · 0 이상) · 최소 청구 기준액(min_claim_limit, 기본 −100,000원 · 0 이하) — VAT 포함 실지급 총액 기준(payout_threshold_basis = VAT_INCLUDED)이며 수취인 분할 계약은 수취인 단위로 판정한다. 범위를 벗어나면 저장 차단 "지급 기준액은 0 이상, 청구 기준액은 0 이하로 입력해 주세요."(합의서 v3.9.11 §7.3)
- [공통] 지급 이월은 지급 시점만 늦춘다. 원천징수 확정과 신고 귀속월은 실제 지급 · 적법한 상계 · 법정 지급 의제 사건이 성립한 때로 판정하며, 계산 · 마감만 끝난 미지급 금액은 원천징수 미발생 상태로 남는다(합의서 v3.9.0 §7.3)
- [공통] 환급 부담 방식(refund_promo_burden_type) — 옵션 A · B · C 중 계약서 선택값을 기록한다. 미선택은 주의 "환급 부담 방식이 아직 선택되지 않았습니다." B · C 는 4단계(DEDUCT)에서 차감하고 MMG 판정 모수에서 뺀다(합의서 §15)
- [개발] 계약 시작일은 마감 구간이 포함되면 잠긴다. 최초 종료일이 시작일보다 앞서면 저장 차단 "계약 종료일을 시작일 이후로 입력해 주세요."

계약 종료 대상별 처리 지정 — 승계 계약 / 매핑 종료
- [공통] 계약 상태를 만료 · 중도 해지로 바꾸면 열린다. 이 계약에 매핑된 강의 · 교재 SKU · 위탁 도서(2차)마다 승계 계약 지정 또는 매핑 종료를 고른다. 하나라도 지정하지 않으면 종료 저장을 차단한다 — "{대상}: 승계 또는 매핑 종료를 지정해 주세요."(합의서 v3.9.11 §5.4 · §16.1)
- [공통] 종료 후에도 판매 · 이용을 계속할 매핑만 승계 계약이 필요하다. 계속하지 않는 매핑은 매핑 종료로 닫으며 승계 계약을 일괄 요구하지 않는다
- [개발] 승계 계약 ID 는 유효 계약 마스터의 유효 계약 중 권리자 구성이 같은 계약만 받는다(계약 합의 당사자 일치 원칙). 비면 "{대상}: 승계 계약 ID를 입력해 주세요.", 현재 계약이면 "{대상}: 현재 계약을 승계 계약으로 지정할 수 없습니다." 승계는 기존 매핑 행 종료일을 피승계 계약 종료일로 두고 승계 계약 contract_id 로 신규 행을 Insert 한다 — 기존 행 Update 금지(§4.3 이력 보존)
- [공통] 금전 약정은 승계하지 않는다 — 선급금 잔액 · MMG · 전속계약금(위약 조항 포함) · 개발지원금 약정은 승계 계약으로 자동으로 넘어가지 않는다. 지원금은 승계 계약에 새 약정을 등록하거나 종료 처리 정책으로 기존 약정을 끝내며, 모계약 종료 연동 약정은 피승계 계약 종료일에 종료된다. 선급금 잔액을 이어가려면 승계 계약에 선급금 원장을 새로 등록하고 정산 수동 조정(ADMN-SETT-005) 대체 전표로 이관한다(§5.4 · 확인 필요 사항 17)
- [공통] 종료된 계약도 후속 정산에서 빠지지 않는다 — 미지급금 · 미회수 채권 · 환불 · 조정 · 미완료 지급 건은 종료된 계약을 참조해 계속 처리한다(제1장 종료 계약의 잔액 조회)
- [UI/UX] 대상 목록은 켜진 조항에서 모은다 — 온라인 R/S 의 강의, 교재 인세의 SKU 연결 저서, 위탁의 위탁 도서. 대상이 없으면 "종료 처리할 연결 상품이 없습니다." 실제 매핑 반영은 상품별 권리자 매핑(ADMN-SETT-001)이 한다

[Term-EXC] 전속계약금 — 회차 · 반환 · 위약 조항
- [공통] 총 약정액(0 초과) · 의무 시작일 · 의무 종료일 · 지급 구조(회차 분할 / 일시 지급). 회차표는 회차 · 귀속월 · 지급 마일스톤 · 금액 · 검수 상태(검수 전 / 확정) · 관리와 회차 합계 행
- [개발] 저장 차단 — "전속계약금 총 약정액은 0보다 커야 합니다." / "전속 의무 기간을 확인해 주세요." / "전속계약금 회차 합계와 총 약정액이 다릅니다." / "일시 지급은 지급 회차가 1건이어야 합니다." / 위약 조항 있음인데 문언 없음 "위약 조항 발동 조건을 입력해 주세요."
- [공통] 확정 회차와 마감 완료월 이하 회차는 잠금이다. 검수 승인은 약정금 마일스톤 검수(ADMN-INST-002), 지급 집행은 월간 정산 및 집행(ADMN-SETT-002)이다. 소득 구분 기본값은 사업소득이며 기타소득 C17 · C19 는 일회성 대가 소명 + 재무 책임자 승인을 거친다(§5.2)
- [공통] 중도 해지 반환 조항 — 잔여기간 일할 반환 / 전액 반환 / 반환 없음. 일할 반환 = 내림(기 지급 실지급액(세후) × 잔여 의무일수 ÷ 총 의무일수), 총 의무일수 = 의무 종료일 − 의무 시작일 + 1, 잔여 의무일수 = 의무 종료일 − 해지일(해지일 당일은 복무일수에 포함). [일수·반환액 산출]은 해지일 · 세후 기준액을 받아 결과만 보여 주고 반환 청구 원장에는 반영하지 않는다(§5.2)
- [공통] 반환액은 반환 · 청구 단계(10단계 CLAIM)에서 1회만 반영한다 — 수취인 분할(8단계) · 지급 판정(11단계)에서 다시 차감하지 않는다. 상계는 동일 계약 · 동일 수취인 범위에서 허용 요건과 승인 근거가 있을 때만 하고, 당월 과세표준을 자동 차감하지 않으며 원거래 세무 정정은 따로 처리한다(합의서 v3.9.0 §5.2 · §8.3)
- [공통] 위약 조항(있음) — 산정 방식(배율 / 정액) · 배율 % · 산정 기준액(약정 총액 / 기지급액, 세전 액면) · 위약금 정액 · 일할 반환과의 관계(위약금에 포함 / 병과) · 발동 조건 문언(최대 500자) · 상계 동의. 위약금은 정산 엔진 어느 단계에도 넣지 않고 발동 · 청구는 위약금 원장(설계 예정)에서 관리한다 — 확인 필요 사항 18

[Term-DEV] 개발지원금 — 지급 방식 · 한도 · 요율 라인 · 대상 · 누계
- [공통] 지급 방식(support_fund_payment_method) — 매출연동 REVENUE_SHARE / 분할 지급 INSTALLMENT / 일시금 LUMP_SUM(기본값 · 부록 B). 분할 · 일시금은 총 약정액 · 미지급 회차 수 · 지급 회차표가 열린다 — 합계가 다르면 "지원금 총 약정액과 지급 회차 합계를 확인해 주세요.", 일시금 회차가 1건이 아니면 "일시금 지원은 지급 회차가 1건이어야 합니다."
- [공통] 매출연동 개발지원금(Pipeline 5.1) 산식(합의서 v3.9.0 §5.2) — 지원금 발생액 = 정산 기준금 × 지원금 요율. 자사 지분율을 추가로 곱하지 않는다. 자사 배분가능액 = 정산 기준금 × 자사 지분율이 지급 재원이고, 자사 최종 잔여액 = 자사 배분가능액 − 지원금 확정액 합계다. 예) 자사 지분 50% · 지원금 요율 15% → 지원금은 기준금의 15%, 자사 잔여는 35%
- [공통] 지원금 요율의 단일 원천은 SUPPORT 요율 라인(rate_type = SUPPORT · agreement_id 필수)이다 — 약정 테이블에 요율을 두지 않는다(v3.8.5 §5.1). 산정 모수는 정산 기준금(rate_basis = SAME_AS_BASIC 단일값 — 온라인 강좌는 강의 기준금, 교재는 확정 부수 × 인세 기준가). 저장 차단 — "SUPPORT 요율 라인이 필요합니다." / "동일 지원금 약정의 요율 기간이 중첩됩니다." / "SUPPORT 요율 기간이 약정 종료일을 초과합니다."
- [공통] 정산 대상(support_fund_agreement_targets) 1건 이상 — 강의(LECTURE) · 자사 발행 도서 SKU(BOOK_SKU). 비면 "지원금 대상을 1건 이상 선택해 주세요." 저장 시점에 자사 권리자 지분이 0보다 큰 대상만 받는다 — "{대상}: 자사 지분이 0보다 커야 합니다." 동일 콘텐츠 · 동일 기간 SUPPORT 요율 합계가 자사 지분을 넘으면 저장 차단 — "{대상}: 지원금 요율 합계 N%가 자사 지분 N%를 초과합니다." 위탁 도서 · 일반 상품은 대상이 될 수 없다
- [공통] 정산 범위(settlement_scope)는 대상에서 파생 표시한다 — 강의만 TRACK_A_ONLY(온라인 강좌 수익배분(Pipeline 1.1) 한정 · 기본) / 교재만 TRACK_B1_ONLY(자사 발행 도서 인세(Pipeline 2.1) 한정) / 둘 다 TRACK_A_B1(합산). 교재 대상이 있는데 인세 조항에 SKU 연결 저서가 없으면 주의 "교재 지원금 대상에 연결된 인세 계약 SKU를 확인해 주세요."(출간 전 계약이 정상이라 저장은 막지 않는다) — 확인 필요 사항 24

Lock 대상 — 시작일 vs 만료일 |
IA 확정 사양 ③은 "요율 및 시작일 수정 차단". 설계서 §3.2.2 ADMN-INST-001은 "요율 및 만료일 수동 변경 차단"으로 서로 다르게 적혀 있다 |
요율 · 개시일은 Lock 한다 — 정산에 적용된 계약 요율은 수정할 수 없다. 만료일도 과거 일자로는 수정할 수 없다 — 기 발생 거래일보다 앞으로 당기는 저장은 서버에서 거부하며, 연장 방향의 수정만 허용한다 |

중도 해지 시 기 발생 정산 처리 |
해지일 이전에 결제된 강좌의 미확정 정산분(당월 진행분)을 정상 지급할지, 해지 조건에 따라 보류/차감할지 IA·설계서 모두 미기재. 환불이 해지 이후 들어오면 마이너스 정산이 발생하는데 지급 대상이 없는 강사에게 어떻게 환수할지도 공백 |
중도 해지일을 기준으로 계약이 종료된 것으로 본다. 해지일 이전에 기 발생한 정산은 지급을 유지한다. 종료 이후 정산에서 마이너스 금액이 나오면 자동 상계하지 않고 수동으로 처리한다 |

계약 기간 중첩 허용 범위 |
1:N 구조상 전속 계약 + 특강 계약이 병존할 수 있으나, 같은 상품에 유효 계약이 2건 겹치면 거래일 스냅샷이 어느 요율을 집을지 모호하다. IA·설계서 모두 우선순위 규칙 미기재 |
우선순위 규칙을 두지 않는다. 상품별 권리자 매핑(ADMN-SETT-001)에서 권리자 행마다 적용할 계약을 직접 고르는 방식으로 확정한다(PO 2026-09-22 · 합의서 v3.9.11 §4.2 · §4.3 · §16.1). 매핑 행이 contract_id 를 NOT NULL 로 보유하므로 같은 상품에 유효 계약이 2건 겹쳐도 어느 요율을 집을지 모호하지 않다. 같은 계약 · 같은 rate_type 의 기간 중첩 요율 라인은 저장을 차단한다(합의서 §5.1). 기존 등록분은 계약 지정 이마이그레이션을 거치며, 미지정 상품은 정산 매핑 미완료로 배치 인입을 막는다 |
