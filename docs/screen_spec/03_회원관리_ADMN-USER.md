StarPlayer+ DRM 등록 기기 제어 — 이 화면의 핵심
- [UI/UX] 설계서 [DRM 제어] 요건 — "StarPlayer+ 등록 기기(Device) UUID 목록 실시간 조회 및 수동 기기 리셋 원클릭 기능". 기기 등록 한도는 모바일 앱 2대이고 PC 는 기기 수를 제한하지 않는다(확정 · PO 2026-09-09 · ADMN-CONF-003). PC 는 동시 재생 1 세션으로만 통제한다. 따라서 모바일 기기를 바꾼 회원은 반드시 이 화면을 거쳐야 새 기기에서 다시 재생할 수 있다
- [공통] 실시간 조회는 캐시가 아니라 DRM 서버 조회다. 구분(PC/모바일) · Device UUID · 기기 정보(OS·브라우저/앱 버전·접속 지역) · 최초 등록 · 최근 재생을 표시한다
- [UI/UX] 상단 배너는 모바일 등록 대수 / 한도를 표기하고, 한도에 도달(2/2)하면 빨강으로 한도 초과를 알린다. PC 는 대수 한도가 없으므로 배너에 제한 없음으로만 적고, PC 행의 제어 칸에는 리셋 버튼을 두지 않는다 — PC 재생이 막히는 경우는 기기 한도가 아니라 동시 재생 세션(ADMN-CONF-003) 문제다
- [UI/UX] [기기 리셋] 원클릭 처리 순서
- ① 사유 입력 모달(정형 + 상세, 필수) — 사유 없이는 진행 불가
- ② device_map에서 해당 UUID 삭제 + user_course 단말 카운트 즉시 갱신
- ③ StarPlayer+ 단말 등록 해제 API 호출 — DRM 측 등록이 실제로 풀려야 재생이 된다
- ④ 수강 종료일 동적 싱크 — 리셋과 함께 해당 계정의 콘텐츠 만료일을 DB 기준으로 재전송해 DRM과 DB를 일치시킨다
- ⑤ 타임라인 INSERT + 토스트 "모바일 기기가 초기화되었습니다. 회원이 새 기기에서 재로그인하면 자동 등록됩니다"
- [공통] ②③④는 한 트랜잭션으로 묶는다. DRM API가 실패했는데 DB만 지워지면 "관리자 화면상 0대인데 실제로는 재생 불가"라는 재현 불가 CS가 만들어진다. API 실패 시 DB 변경을 롤백하고 오류를 그대로 노출한다
- [공통] 리셋 남용 방지(제안) — 동일 회원 월 3회를 초과하면 경고를 띄우고 4회째부터는 상급자 승인을 요구한다. 무제한 리셋은 계정 공유를 사실상 허용하는 것과 같다. '기기 초과 차단 발생 횟수'를 함께 보여주는 이유도 계정 공유 판별을 위해서다 — 짧은 기간에 서로 다른 지역에서 차단이 반복되면 블랙리스트(ADMN-USER-005) 검토 대상이다
- [공통] [모바일 기기 전체 리셋]은 등록된 모바일 2대를 한 번에 해제한다. 기기 분실·계정 도용 신고 시 사용하며 사유 입력은 동일하게 필수다
